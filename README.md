# aozora-history

GMOあおぞらネット銀行の「つかいわけ口座」を記録して、ダッシュボードで見られるようにする
Firefox 拡張機能(デスクトップ / Android)。

銀行サイトにはつかいわけ口座間の振替履歴を見る画面がない。
この拡張は、サイトを普段どおり使っているあいだに記録を残す。

- 記録は `browser.storage.local` に保存する。外部へ出るのは R2同期を設定したときだけ
- 端末間で記録を共有したい場合は、自分の Cloudflare R2 バケットを使う

## インストール

[Firefox Add-ons (AMO)](https://addons.mozilla.org/firefox/addon/aozora-history/) から。
Android版Firefox も同じページからインストールできる。

Nix (home-manager) の場合:

```nix
inputs.aozora-history.url = "github:Xantibody/aozora-history";

programs.firefox.profiles.<profile>.extensions.packages = [
  inputs.aozora-history.packages.${system}.default
];
```

## 記録するもの

| 記録                                 | いつ                                                                       | 取得元        |
| ------------------------------------ | -------------------------------------------------------------------------- | ------------- |
| つかいわけ口座の残高                 | 一覧ページを開いたとき / 銀行サイトの画面遷移 / ダッシュボードを開いたとき | DOM / 銀行API |
| 振替(出金口座・入金口座・金額)       | 振替ページで「確認」を押したとき                                           | DOM           |
| 入出金明細(代表口座・つかいわけ口座) | 銀行サイトの画面遷移 / ダッシュボードを開いたとき                          | 銀行API       |
| 定額自動振替の設定                   | 銀行サイトの画面遷移 / ダッシュボードを開いたとき                          | 銀行API       |
| 定額自動振込の契約                   | 銀行サイトの画面遷移 / ダッシュボードを開いたとき                          | 銀行API       |

- 残高は前回から変わったときだけ保存する
- 銀行APIへの問い合わせは、ログイン中のタブと同じセッションで裏側から行う。
  定期的なポーリングはしない。機会はログイン後の画面(`/bank/…`)へ移ったときで、
  そこから10分は再び問い合わせない(SPAの画面遷移ごとに叩き続けないための下限)
- ダッシュボードを開いた時点でも取り込む。こちらは10分の下限を待たない
  (開くこと自体が「いまの残高が見たい」という合図なので)。
  銀行サイトのタブでしか取りに行けないため、開いているタブに頼む形になる。
  開いていなければ何も呼ばず、ヘッダーにその旨を出すだけにする
- 振替を記録すると画面右下にコメント欄が出る。その場で用途を書ける(取り消しもここから)
- 銀行サイトはセッションが切れていても完了表示を出すことがある。
  セッション切れの案内が見えているあいだは記録しない

### 記録にない移動の拾い直し

つかいわけ口座の残高は、振替ページを経由せずにも動く。

- 定額自動振替
- つかいわけ口座を引落口座に指定した自動引落
- 別端末・スマホアプリからの振替

これらを外部入出金として扱うと、口座間で動いただけの金額が出金と入金の両方に立ち、収支が狂う。
そこで、同じスナップショット区間で打ち消し合う増減は1件の振替として組み直し(「自動」ラベル付き)、
残った分だけを外部入出金とする。出金側・入金側を絞れないときは推測せず、差額のまま残す。

### 定額自動振込の見分け

外部への振込は、明細の摘要に相手先しか出ない。毎月の決まった振込なのか、その月だけの
振込なのかが読めないため、銀行に登録した定額自動振込の契約と突き合わせる。
金額が一致し、摘要に契約の受取人名が入っていれば「定額自動振込」のラベルを付ける
(銀行側でグループに用途を書いてあれば、ラベルの説明に添える)。

## ダッシュボード

ツールバーのボタンから開く。ページは2つで、狭い幅では下部のタブバーで切り替える。

| ページ | 内容                                                                        |
| ------ | --------------------------------------------------------------------------- |
| ログ   | 振替・外部入出金・代表口座の明細・残高記録を1本の時系列にした日ごとのカード |
| 残高   | 口座カード、合計残高の推移パネル、残高スナップショットの一覧                |

ヘッダーには表示月(◀▶ で移動、開始日・終了日の詳細指定も可)、合計残高、
最終記録・最終同期の時刻が出る。7日以上記録が増えていなければ警告を出す
(銀行サイトの構造変更で記録が静かに止まったことに気づけるように)。

開いた時点の取り込みの状況も同じ場所に出る。走っていれば「取り込み中…」、
銀行サイトのタブが無くて取り込めなければ「銀行サイトを開くと更新されます」。
ここから銀行サイトを開く導線は置いていない。銀行のセッションは短く、
拡張から開いてもログイン画面が出るだけに終わるため。

明暗はヘッダーのボタンで システム → ライト → ダーク と切り替える。
既定はシステムで、OSの設定に従う。選んだ明暗はその端末だけに残る(同期しない)。

### ログ

- 上部の口座チップで口座を絞り込む
- フィルタは すべて / 振替 / 入金 / 出金
- 各行にコメントを付けられる(過去のコメントが候補に出る)
- 振替は削除できる(デスクトップは `×`、モバイルは左スワイプ)
- 新しい順に100件ずつ。続きは「さらに表示」で足す

### 残高

- 口座カードには残高・期間内変動・構成比・振替と外部入出金のKPI
- 推移パネルで区間を選ぶとログ側の絞り込みになり、グラフから明細へ降りられる
- グラフに文字は置かない。最新の合計・期間の両端・破線の出来事は図の外に出す
  (SVGは幅なりに縮むため、中の文字は狭い画面で読めなくなり互いに重なる)
- スナップショット一覧も新しい順に100件ずつ

### 設定

R2同期、インポート / エクスポート、デバッグ。

デバッグ欄(既定は非表示)には、最後に銀行APIから取り込んだ結果がAPIごとに出る。
取り込みは裏で走るため、銀行側の仕様変更で失敗しても画面には何も出ない。それに気づくための欄。
「今すぐ取り込む」で10分の間隔を待たずに走らせられる。

## 端末間の同期 (Cloudflare R2)

PC・モバイルのFirefox間で記録を共有できる。

1. Cloudflare で R2 バケットを作る
2. 「オブジェクトの読み取りと書き込み」権限で R2 の APIトークンを発行する
3. 各端末の設定画面で、アカウントID・バケット名・アクセスキーID・シークレットを入力する

2台目以降は、設定済みの端末で「同期設定をエクスポート」したJSONを取り込めばよい。
シークレットが平文で入るため、取り込んだらファイルは削除すること。

設定後の動きは次のとおり。

- 記録が変わると数秒後に自動で同期する
- ダッシュボードを開いたときに他端末の記録を取り込む(「今すぐ同期」で手動も可)
- マージは和集合。コメントが衝突したら編集が新しい方を採る。
  削除も編集として扱うため、他端末に残る古い記録で復活することはない

> [!WARNING]
> 認証情報は `browser.storage.local` に平文で保存される。
> このバケット専用のAPIトークンを使うこと。

## データの持ち出し

R2上のオブジェクトは素のJSON(`{snapshots, transfers, statements, comments, deletions}`)で、
wrangler からそのまま取れる。

```sh
npx wrangler r2 object get <バケット名>/aozora-history.json --file aozora-history.json
```

設定画面の「インポート / エクスポート」でできること:

- このJSONを読み込んで現在の記録とマージする
- 現在の記録を同じ形式でダウンロードする
- 振替履歴と代表口座の明細をCSVで出す(家計簿ソフト向け)

## 制限

- 振替の「記録」は、この拡張が動いているブラウザでの操作しか残せない。
  拡張を入れる前や別端末からの振替は記録にならないが、残高スナップショットが両端に残っていれば
  口座間の移動として拾い直される
- 拾い直しは、1つのスナップショット区間に移動が1つであることを前提にしている。
  定額自動振替と自動引落が同じ区間で重なるなど増減が打ち消し合わない場合は分離できず、
  差額のまま外部入出金として残る
- 入出金明細は口座ごとに最新100件まで。それより前は取り込めない
- つかいわけ口座ごとの明細を取る画面は銀行サイトのメニューから辿れず、いつ仕様が変わってもおかしくない。
  取得した明細の最新残高がその口座の残高と一致しない場合は取り込まない。
  取り込めなくても外部入出金が摘要なしの「外部」表示に戻るだけで、残高と収支の集計は変わらない

## 開発

[Nix](https://nixos.org/) と [direnv](https://direnv.net/) で環境を作る。
Node.js / pnpm / tsgo / oxfmt / oxlint は flake.nix の devShell が提供する。

```sh
direnv allow   # 初回のみ。direnv を使わない場合は nix develop
pnpm install
pnpm verify
```

| コマンド                           | 内容                                          |
| ---------------------------------- | --------------------------------------------- |
| `pnpm verify`                      | fmt:check → lint → typecheck → knip → test    |
| `pnpm fmt` / `fmt:check`           | oxfmt でフォーマット / チェックのみ           |
| `pnpm lint` / `typecheck`          | oxlint で静的解析 / tsgo で型チェック         |
| `pnpm knip`                        | 使われていない export・ファイル・依存を探す   |
| `pnpm test` / `test:watch`         | vitest で全テスト / ウォッチ                  |
| `pnpm test:logic` / `test:dom`     | node で走る分だけ / Firefox で走る分だけ      |
| `pnpm dev`                         | ダミーデータのダッシュボードをブラウザで開く  |
| `pnpm build`                       | esbuild と tailwind で dist/ にビルド         |
| `pnpm package:local`               | ローカル用 xpi を作成                         |
| `pnpm package:firefox` / `:source` | `VERSION` 付きの xpi / ソースアーカイブ(CI用) |

### ダミーデータで動かす

画面を直すあいだは `pnpm dev` が速い。拡張として読み込む代わりに `browser.storage` と
`fetch` をメモリ上のフェイクに差し替え(`src/dev/`)、ダミーの記録を入れてから
同じダッシュボードを起動する。保存すると再ビルドされるので、拡張を入れ直さなくてよい。

```sh
pnpm dev   # http://localhost:8000/dashboard.html
```

ダミーは `?data=` で切り替える。

| `?data=`     | 中身                                                      |
| ------------ | --------------------------------------------------------- |
| `rich`(既定) | 120日ぶん。給与・家賃・定額自動振替・メモ・同期設定を含む |
| `empty`      | 記録なし。空状態の確認用                                  |
| `dense`      | 420日ぶん。ページングとグラフの間引きの確認用             |

給与や家賃の額を並べただけでは、画面の作りは確かめられない。記録に残らない
定額自動振替を差額から拾い直す、口座別明細から外部入出金の摘要を当てる、といった
噛み合わせが要る。ダミーは月の流れを組み立てて、そこから残高・明細・記録を導いている
(`src/dev/dummy-data.ts`)。R2同期もメモリ上の置き場に向くので、外へは何も出ない。

記録は開くたびに作り直すため、消しても壊しても構わない。

拡張として通しで確かめるときは `pnpm build` のあと、Firefox の
`about:debugging#/runtime/this-firefox` → 「一時的なアドオンを読み込む」で
`dist/manifest.json` を選ぶ。

未使用の export は oxlint も tsgo も拾えない。どちらも「未使用」を1ファイルの中でしか
見ず、`export` が付いた宣言は外から使われる可能性があるものとして扱うため
(oxlint 1.71 に `import/no-unused-modules` は無い)。プロジェクト全体の
import グラフを見る `pnpm knip` がその役を持つ。理由は `knip.config.ts` にも書いてある。

検査は `.github/workflows/checks.yml`(静的解析・node のテスト・Firefox のテスト・
build を独立したジョブで並列実行)に書いてあり、`ci.yml`(push / PR)と
`release.yml` の両方がこれを呼ぶ。リリースは検査に `needs` で続くので、
同じ検査を通ってからしか成果物が出ない。ツールは CI でも nix
(`.github/actions/setup`)から取るため、環境差異が出ない。

### テストの置き場所

走る場所で2つに分かれる。ファイル名で決まる。

| ファイル        | 環境               | 中身                                 |
| --------------- | ------------------ | ------------------------------------ |
| `*.test.ts`     | node               | DOMを触らない計算・入出力・書式・CSV |
| `*.dom.test.ts` | Firefox (headless) | 画面を組んで読むもの全部             |

jsdom は使わない。緑になっても Firefox で動く保証がなく、`matchMedia` や
`location` をスタブで埋める手間だけが残る。実際、`hidden` クラスが
`inline-flex` に負けてメモの誘い文が消えない不具合は、jsdom では緑のまま
すり抜けていた(`42cb8bd`)。

見た目の検証はクラス名の文字列ではなく、`getComputedStyle` と
`getBoundingClientRect` と `checkVisibility()` で実際の結果を問う。土台が
崩れていないかは `src/dashboard/styles.dom.test.ts` が見張っている。

ブラウザは playwright のダウンローダではなく nixpkgs から渡す。
Firefox だけを選んだ導出(`.#playwright-browsers`、271MiB。既定の
`playwright-driver.browsers` は chromium/webkit まで含めて 1.1GiB)を、
devShell と CI が同じものとして参照する。**`package.json` の `playwright` は
flake の `playwright-driver` と同じ版に固定すること。** ずれると
`firefox-<revision>` が見つからず起動できない。

検査に使う道具立ては `flake.nix` の `.#toolchain` が持つ。devShell も CI も
これ一つを読むので(CI は `nix profile install .#toolchain`)、一覧を
ワークフロー側に書き写す必要がない。

### リリース

`manifest.firefox.json` と `package.json` の `version` をタグに揃えてから `v*` タグを push すると、
`.github/workflows/release.yml` が動く。

1. `checks.yml` の検査を並列で通してから xpi をビルド
2. GitHub Release を作成(xpi を添付)
3. AMO へ提出(要 `AMO_JWT_ISSUER` / `AMO_JWT_SECRET`)

審査を通過すると `update-flake-amo.yml`(6時間ごと)が flake.nix の xpi URL とハッシュを
署名済みのものへ自動更新する。
